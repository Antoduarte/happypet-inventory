PASOS PARA MONTAR HAPPYPET-INVENTORY EN LA COMPUTADORA DEL CLIENTE
=================================================================
Python 3.12 + Apache 2.4 + mod_wsgi. El cliente YA tiene Apache
sirviendo otro proyecto (happypet) con la misma configuracion.
NO se toca nada de lo que ya funciona.

------------------------------------------------------------------
PASO 1 - Copiar el proyecto
------------------------------------------------------------------
1. Copiar la carpeta "backend" completa a la maquina del cliente:
       C:\Apache24\htdocs\happypet-inventory
   Debe incluir: config\, happypet\, manage.py, requirements.txt,
   static\ y el archivo .env (con DATABASE_URL).

------------------------------------------------------------------
PASO 2 - Configurar el archivo .env
------------------------------------------------------------------
2. Editar el archivo .env (en C:\Apache24\htdocs\happypet-inventory)
   y AGREGAR la siguiente linea (es obligatoria):
       DJANGO_ALLOWED_HOSTS=inventory.local
   Sin esto, Django responde "400 Bad Request" en produccion
   (el valor por defecto es .onrender.com).

------------------------------------------------------------------
PASO 3 - Instalar el entorno virtual
------------------------------------------------------------------
3. Ejecutar el instalador (una sola vez):
       C:\Apache24\htdocs\happypet-inventory\deploy\setup_inventory.bat

   Lo que hace:
       - Crea venv con Python 3.12        (py -3.12 -m venv venv)
       - Instala dependencias             (pip install -r requirements.txt)
       - Instala mod_wsgi cp312           (pip install mod_wsgi)
       - Aplica migraciones               (python manage.py migrate)
       - Recopila estaticos whitenoise    (python manage.py collectstatic)

   NOTA: gunicorn (en requirements) NO se usa en Windows.
   El servidor real es mod_wsgi. Si "pip install mod_wsgi" falla,
   verificar que Python 3.12 de 64 bits este instalado.

   NOTA IMPORTANTE: El proyecto usa pdfkit + wkhtmltopdf para imprimir
   tickets. Asegurarse de que el cliente tenga instalado wkhtmltopdf en:
       C:\Program Files\wkhtmltopdf\bin\wkhtmltopdf.exe
   Si no esta instalado, descargarlo de https://wkhtmltopdf.org/downloads.html
   Si el venv ya tenia xhtml2pdf instalado, desinstalarlo:
       pip uninstall xhtml2pdf -y

   NOTA SOBRE EL ERROR "RevocationCheckingPolicy() takes no arguments":
   Ese error viene de xhtml2pdf en su cadena de dependencias (pyhanko).
   Si aparece, la solucion es:
       1. Editar requirements.txt: cambiar xhtml2pdf por pdfkit.
       2. pip uninstall xhtml2pdf -y
       3. pip install pdfkit
   El codigo ya fue migrado a pdfkit en happypet/sales/views.py.

------------------------------------------------------------------
PASO 4 - Configurar Apache (VirtualHost nuevo)
------------------------------------------------------------------
4. Abrir C:\Apache24\conf\httpd.conf y AGREGAR AL FINAL este bloque:

   Listen 8080

   <VirtualHost *:8080>
       WSGIScriptAlias / "C:/Apache24/htdocs/happypet-inventory/config/wsgi.py" application-group=inventory

       <Directory "C:/Apache24/htdocs/happypet-inventory">
           Require all granted
       </Directory>
   </VirtualHost>

   Y si happypet sigue en config global, agregarle tambien su grupo:
   en la linea WSGIScriptAlias de happypet, al final poner
   application-group=happypet (asi no comparte sub-interprete).

   NOTA 1: LoadFile python312.dll, LoadModule wsgi_module y
   WSGIPythonHome ya estan configurados globalmente (los usa el
   proyecto que ya funciona). No se duplican.

   NOTA 2: WSGIPythonPath NO puede ir dentro de <VirtualHost> en
   Windows (da error de sintaxis). El path del venv propio lo
   maneja el archivo config\wsgi.py del proyecto (sys.path.insert).

   NOTA 3 (IMPORTANTE): con dos proyectos en un mismo Apache, mod_wsgi
   comparte el interprete. Para que cada uno use SU Django, es OBLIGATORIO:
   - wsgi.py con asignacion directa (NO setdefault):
       os.environ['DJANGO_SETTINGS_MODULE'] = 'config.settings.production'
   - django-environ leyendo con overwrite=True:
       env.read_env(BASE_DIR/.env, overwrite=True)
   - application-group distinto en cada WSGIScriptAlias.
   Esto ya esta aplicado en el codigo del proyecto (config/wsgi.py y
   config/settings/base.py).

------------------------------------------------------------------
PASO 5 - Agregar el dominio en el archivo HOSTS
------------------------------------------------------------------
5. Ejecutar (doble clic) el archivo:
       C:\Apache24\htdocs\happypet-inventory\deploy\editar_hosts.bat
   Se abrira el Notepad como administrador (aceptar el cartel de UAC)
   con el archivo hosts ya cargado.
   Agregar la linea:
       127.0.0.1 inventory.local
   y guardar.

------------------------------------------------------------------
PASO 6 - Reiniciar Apache y validar
------------------------------------------------------------------
6. Verificar sintaxis:    C:\Apache24\bin\httpd -t
   (debe decir "Syntax OK")

7. Reiniciar el servicio Apache2.4:
       net stop Apache2.4 && net start Apache2.4
   (o desde "Servicios" / services.msc)

8. Probar en el navegador:
       http://inventory.local/admin/
   y un endpoint de la API (ej. /api/... ).

9. Si algo falla, revisar el log:
       C:\Apache24\logs\error.log

------------------------------------------------------------------
NOTAS / ERRORES FRECUENTES
------------------------------------------------------------------
- 400 Bad Request            -> DJANGO_ALLOWED_HOSTS mal configurado.
- Error al iniciar httpd     -> LoadFile debe apuntar al python312.dll
  del cliente, y el .pyd debe ser cp312 (no cp38).
- /admin/ no mantiene sesion por HTTP plano -> es normal: en
  produccion las cookies son Secure. La API con JWT (header
  Authorization: Bearer ...) funciona siempre.
- Si inventory importara Django 4.2 en vez de 6.0 (conflicto de
  sys.path) -> el WSGIPythonPath del vhost ya apunta primero al
  venv propio; si aun asi falla, avisar para usar reverse proxy
  con waitress como plan B.
